# News-based Predictor

Репозиторий модели проекта СНО НИЯУ МИФИ **«Анализ влияния новостного фона на поведение
финансовых рынков»**.

## Идея

Финансовые рынки в теории почти мгновенно "отыгрывают" новости в цене (гипотеза эффективного
рынка). Вопрос, который проверяет проект: остаётся ли всё-таки измеримое окно, где новостной фон
ещё не полностью учтён в цене — и можно ли его использовать, чтобы предсказать движение котировок
на коротком горизонте.

В качестве кейса выбраны акции Сбербанка (SBER) на 5-минутных свечах и поток новостей РИА за год.

## Как это устроено

1. **Данные.** Рыночные свечи и новости лежат в двух SQLite-базах (`market_data_clean.db`,
   `ria_news_all_2025.db`), не входят в репозиторий — см. [Данные](#данные).
2. **Эмбеддинги новостей.** Каждая новость превращается в вектор через мультиязычную SBERT-модель
   [`intfloat/multilingual-e5-large`](https://huggingface.co/intfloat/multilingual-e5-large)
   (1024-мерный эмбеддинг) — подходит для русскоязычных текстов и семантического поиска.
3. **Взвешенная агрегация по времени.** Для каждой свечи новости из скользящего окна (30/60/120/240
   минут) агрегируются не простым усреднением, а с экспоненциальным затуханием веса по свежести
   (период полураспада — 30 минут): новость пять минут назад весит больше, чем час назад.
   Агрегируются и эмбеддинги, и простой сентимент (подсчёт позитивных/негативных ключевых слов).
4. **Признаки.** Рыночные (доходности, скользящие средние, волатильность, лаги, объём) + новостные
   (первые 10 компонент PCA от взвешенного эмбеддинга, интенсивность потока новостей, сентимент,
   количество новостей в окне).
5. **Целевая переменная.** Трёхклассовая: рост / нейтрально / падение следующей свечи, по порогу
   доходности ±0.1%.
6. **Модель.** LightGBM-классификатор, кросс-валидация — `TimeSeriesSplit` (а не случайное
   разбиение: в финансовых временных рядах нельзя валидироваться на данных из прошлого относительно
   обучающих), метрика — Macro F1 (три класса неравномерно распределены).
7. **Проверка гипотезы (`comparator.py`).** Отдельный эксперимент сравнивает три модели на
   одинаковом наборе базовых данных: только рыночные признаки / только новостные / их комбинация —
   чтобы измерить прирост качества именно от новостей, а не гадать по одной модели со всеми
   признаками сразу.

## Структура репозитория

| Файл | Назначение |
|---|---|
| `model.py` | Полный pipeline: загрузка данных → эмбеддинги SBERT → взвешенная агрегация → признаки → обучение LightGBM → анализ важности признаков |
| `comparator.py` | Эксперимент Market-only / News-only / Fusion для проверки вклада новостей |
| `requirements.txt` | Зависимости (см. ниже про GPU) |

## Установка

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

⚠️ `requirements.txt` тянет полный CUDA-стек (`torch`, `nvidia-cublas`, `nvidia-cudnn` и т.д.) —
предполагается, что вычисление эмбеддингов идёт на GPU. Без GPU шаг с эмбеддингами (`model.py`)
отработает на CPU, но заметно медленнее; `comparator.py` эмбеддинги не считает и от GPU не зависит.

## Данные

Проект ожидает в папке `data/` (не входит в репозиторий, см. `.gitignore`) две SQLite-базы:

- `data/market_data_clean.db` — таблица `sber_5min` с колонками `datetime, open, high, low, close, volume`
- `data/ria_news_all_2025.db` — таблица `news` с колонками `id, title, published, full_text, tags`

## Запуск

```bash
python model.py       # полный pipeline с эмбеддингами SBERT и обучением модели
python comparator.py  # сравнение Market-only / News-only / Fusion
```
